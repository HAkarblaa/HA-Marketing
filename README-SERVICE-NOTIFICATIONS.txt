إصلاح إشعارات مقدم الخدمة — ملفات التعديل فقط

طريقة التركيب:
1. افتح Supabase > SQL Editor. انسخ محتوى SERVICE-PROVIDER-NOTIFICATIONS-FIX.sql واضغط Run.
   شغّله بعد التحديثات السابقة، ولا تعيد تشغيل ملفات SQL القديمة بعده.
2. استبدل هذه الملفات في مجلد الموقع نفسه ثم انشر التحديث:
   provider-dashboard.html
   notifications.js
   firebase-messaging-sw.js
3. افتح التطبيق بحساب مقدم الخدمة المعتمد. اضغط «تشغيل إشعارات الموبايل» واسمح بالإشعارات حتى تظهر «الإشعارات الخارجية مفعّلة».
4. أرسل طلبًا جديدًا من حساب زبون آخر. جرّب طلبًا مباشرًا لمقدم الخدمة، وطلب القسم، واستمارة الخدمة العامة. جرّب أيضًا والتطبيق بالخلفية.

التعديل يشمل:
- إنشاء إشعارات الطلب المباشر، وطلب القسم لمقدمي نفس الاختصاص، وطلبات استمارة الخدمة العامة حسب اسم الاختصاص.
- الربط بصاحب ملف الخدمة المعتمد والفعال، بدون شرط الرصيد، وبدون حصر بمحافظة معينة.
- إشعار واحد للحساب حتى لو عنده أكثر من ملف خدمة بنفس الاختصاص.
- ظهور الطلبات من المسارات الثلاثة في لوحة مقدم الخدمة، مع المرفقات وأزرار القبول والتقدم والإكمال.
- فتح الطلب الصحيح من الإشعار حتى لو رقم الطلب متكرر بين المسارين.
- إشعارات تغير الحالة للزبون، وإلغاء الزبون لمقدم الخدمة. إلغاء الطلب غير المخصص يبلغ الذين وصلهم الطلب.
- استعادة الإشعارات المفقودة للطلبات المفتوحة الحالية فقط. تكرار تشغيل SQL لا يكرر الإشعارات.
- تجديد ربط جهاز الإشعارات بالحساب، وعرض إشعارات الموبايل أثناء فتح الصفحة، وتصحيح روابط فتح الطلب في الخلفية ومنع العرض المكرر.

هذا تحديث للمشروع الحالي، وليس تثبيتًا مستقلًا. ملف SQL يضيف الربط ويستخدم دالة send-fcm-push الموجودة في مشروع Supabase نفسه وإعدادات Firebase الحالية. لا يغير ملفات الطلبات أو التوصيل الخاصة بالتسوق.

إذا ظهر الطلب والإشعار داخل الموقع ولم يصل إشعار خارجي بعد تفعيله:
راجع آخر إشعارات الخدمة في Supabase SQL Editor بهذه القراءة فقط:
select id, user_id, title, link, push_sent_at, push_attempted_at, push_error
from public.notifications where department='services'
order by created_at desc limit 20;

no_registered_devices يعني أن جهاز صاحب الخدمة غير مربوط بحسابه. فعّل الإشعارات من حسابه ثم اختبر طلبًا جديدًا.
إذا زر التشغيل يعرض أن المتصفح لا يدعم إشعارات الويب، فنسخة التطبيق تحتاج دعم إشعارات من ملفات تطبيق الموبايل نفسه؛ هذه الحزمة تعدل ملفات الموقع وقاعدة البيانات.
أخطاء Firebase الأخرى تظهر في push_error أو في سجل دالة send-fcm-push، وتحتاج معالجة إعدادات الإرسال بحسب الخطأ المسجل.

التحقق: اختبارات محلية على SQL الفعلي والواجهة وربط الجهاز ومسار تسليم الإشعار للإرسال. لم يتم إرسال إشعارات فعلية إلى أجهزة المستخدمين، ولم يتم تشغيل SQL على قاعدة البيانات الحية.
